# インポートとファイル保護

## 操作と配置

ZIP / 7z / フォルダー / 単独ファイルを、ファイル選択またはライブラリへのDropで受け付けます。
処理はStagingの所有UUIDディレクトリで実行し、元ZIPや元フォルダーを移動・削除しません。
展開後にScenario / Vehicleヘッダーを調べ、件数・配置先・容量・競合・警告をプレビューします。
ユーザーは配置先を変更して再解析できます。

アーカイブ内の唯一のScenariosフォルダーにすべてのファイルが入っている場合は、その中身をrootへ配置します。
単独シナリオや複数フォルダー構成は階層を保持します。
Scenarios以外にREADMEや他のフォルダーがある場合、相対参照を壊さないため全体を保持します。
名前だけでファイルの役割を断定したり、車両・モデルを平坦化したりしません。
判断はプレビューの構造説明に表示します。

## 展開制限

| 条件 | 制限 / 対応 |
| --- | --- |
| ファイル・明示ディレクトリ数 | 合計50,000まで |
| 展開合計 | 4 GiBまで |
| 単一ファイル | 1 GiBまで |
| 圧縮比 | 1 MiB超のファイルは1000倍まで |
| パス | 正規化後にroot内部であること、最大240文字 |
| traversal / drive / UNC / ADS | 拒否 |
| デバイス名 / 無効文字 / 末尾ドット・空白 | 拒否 |
| case-insensitive同名ファイル | 拒否 |
| ZIP symlink / reparse、7z LinkTarget、フォルダーjunction | 拒否 |

展開中も実バイト数を数え、宣言サイズとの不一致を拒否します。
未検証の7z特殊リンク形式はSharpCompressが公開するLinkTargetの検出範囲に依存します。
配置先の祖先にreparse pointがある場合も拒否します。

## 確定と復旧

確定直前に元ステージ・配置先のhashとリンク状態を再検査します。
プレビュー後の外部変更を検出したら、変更前に中止します。
競合には確認 / skip / overwriteを指定できます。
overwriteは元ファイルをhash付きでバックアップします。

transaction journalを作り、各ファイルの変更意図を永続化してからatomic copyします。
コピー後に新hashを照合し、installationを保存してCommittedを記録します。
例外・キャンセル時は逆順に復元します。
ユーザーによる追加変更があれば、そのファイルの復旧を中止しjournalを残します。
次回起動は未完了journalの配置先・backup位置・所有UUIDを検証して復旧します。
外部へ向けられたjournalを信用しません。
journal保存後とDB記録後のクラッシュも、未完了状態から同じ経路で処理します。

## 所有権とアンインストール

元から存在するファイルはExisting、新規配置はManagedとして記録します。
Existingはアンインストールで削除・変更しません。上書き前の状態へ戻したい場合は、バックアップ画面で確認して復元できます。
Managedもインストール時のhashと一致する場合だけ削除できます。
変更済み、他installationが所有、外部シナリオから参照されるファイルは保持します。
未知・未登録のファイルやフォルダーをまとめて消すことはありません。
保持対象のパスをUIで確認できます。
履歴とバックアップは設定のインポート画面から操作します。

## 調査範囲

パッケージのオンライン検索、カタログ、自動アップデート、第三者アドオン配信はありません。
BveEXを取り込んで実行することもありません。
ローカルinstallerの選択・起動は別の明示操作です。
